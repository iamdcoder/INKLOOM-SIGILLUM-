The supplied rules permit existing libraries, APIs, frameworks, datasets and open-source components in accordance with their licences. AI, no-code and low-code tools are permitted unless stated otherwise; significant tools and AI-generated components must be disclosed.

**Project control:** Maintain a truthful material register covering code, templates, synthetic fixtures, design assets, datasets, libraries, models, APIs, cloud services and AI assistance. Round 2 submission items include a functional product/prototype/MVP, judge-accessible source repository (unless another method is approved), deployed link/installation/clear demo, architecture and technical-decision explanation, API/model/dataset/library/template/service disclosures, reasonably available user-testing evidence and each member's contribution.

**Project control:** Keep work attributable, reviewable and explainable. The participant must understand, test and be able to defend every meaningful implementation decision. This build uses significant AI assistance; it must not be described as unaided coding.

## 5. Three named improvements tracked through implementation

1. **Proof Ledger and principled abstention.** A finding links to source/version, content location, quote, applicability context and reason code. Missing, conflicting or insufficient proof must not be presented as support.
2. **Scope-Time Truth Resolver.** Resolve configured facts against intended publication time and offer, geography, audience, channel and locale. Preserve historical review context.
3. **Pixel-to-Claim continuity.** OCR text from supported images enters the same claim/terminology checks as text documents while retaining region coordinates and extraction confidence. Visual identity/contrast limits remain explicit.

These improvements have testable MVP implementations and documented limitations; they are not claims of general model accuracy.
